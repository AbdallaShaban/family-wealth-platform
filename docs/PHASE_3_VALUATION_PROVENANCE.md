# Phase 3 — Valuation Provenance & Snapshots

## النطاق

تضيف هذه المرحلة طبقة تاريخية قابلة للتتبع للتقييمات الخارجية واليدوية. لا تنشئ الطبقة أي `financialEvent` أو `journalEntry` أو `journalLine`، ولا تنفذ صفقة أو إعادة تقييم دفترية تلقائية.

## الفصل بين الطبقات

| الطبقة | المصدر | طبيعتها | هل تكتب إلى الدفتر؟ |
|---|---|---|---|
| Ledger Fact | `financialEvents`, `journalEntries`, `journalLines` | حقيقة مالية منشورة أو مسودة | عبر خدمات الدفتر المعتمدة فقط |
| Derived Projection | الأرصدة والحيازات والتقارير | نتيجة مشتقة قابلة لإعادة البناء | لا |
| External Market Data | `priceQuotes`, `fxRates` | قيمة خارجية مؤرخة | لا |
| Valuation Provenance | `valuationProvenance` | مصدر ورمز ووقت وحالة وبيانات lineage | لا |
| Valuation Snapshot | `valuationSnapshots` | قيمة تقييم محفوظة في لحظة محددة | لا |

## Lineage

كل Snapshot مرتبط بـ Provenance. لقطة الأداة ترتبط اختياريًا بـ `priceQuotes`، ويمكن أن ترتبط لاحقًا بـ `fxRates` عند تحويلها إلى عملة الأساس. يحتوي السجل على `asOf` لوقت المصدر و`fetchedAt` أو `capturedAt` لوقت إدخاله في النظام.

لا يجوز أن يتجاوز `asOf` وقت الالتقاط. البيانات التي تجاوزت سياسة التقادم تصنف `stale`، ولا تصلح كتقييم رسمي دون مراجعة. السعر المتأخر من Yahoo يُعرض كـ`delayed` مع الإفصاح عن ذلك.

## سياسة التخزين

السجلات التاريخية Insert-only منطقيًا: التحديث الجديد يضيف Provenance وSnapshot جديدين، ولا يستبدل تاريخًا سابقًا. إعادة المحاولة تنتج سجلًا جديدًا، وتبقى اللقطات القديمة متاحة للتدقيق والمقارنة.

## الخصوصية

يُعرض المصدر والرمز والحالة والتوقيت في القراءة المحمية. لا تخزن Provenance أسرار SMTP أو كلمات المرور أو Tokens أو محتوى اعتماد. القيم المالية لا تُرسل إلى البريد من هذه الطبقة.

## مسار الالتقاط

`Yahoo/FX provider → quote أو fx rate → provenance → valuation snapshot → protected read history`

هذا المسار مستقل عن `Ledger posting`. أي إعادة تقييم محاسبية مستقبلية يجب أن تمر بإجراء دفتر صريح، وموافقة حسب السياسة، وقيد مزدوج متوازن.

## API

الإجراء `family.valuation.history` قراءة محمية ومحدودة إلى 100 سجل لكل طلب. لا توجد Mutation عامة لإنشاء Snapshot في هذه المرحلة؛ الالتقاط يتم من مسارات السعر والـFX الموجودة، مع الاحتفاظ بحدود الصلاحيات الحالية.

## الاختبارات

تغطي اختبارات `server/valuationProvenance.test.ts` تطبيع الرموز، جودة التقادم، ترتيب التوقيت، اكتمال lineage، حالة العملة غير المطابقة، append-only، وحدود عدم الكتابة إلى الدفتر.
