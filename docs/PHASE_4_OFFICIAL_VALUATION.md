# Phase 4 — Official Valuation Read Models

## الهدف

تضيف هذه المرحلة طبقة تقريرية مؤرخة فوق قراءات FAMILY الحالية. اللقطة الرسمية لا تُعد قيدًا محاسبيًا، ولا تعيد تقييم أصل، ولا تنشئ معاملة أو صفقة. مصدر الحقيقة المالي يظل `journal_entries` و`journal_lines` والأحداث المنشورة.

## طبقات البيانات

| الطبقة | المصدر | الاستخدام |
|---|---|---|
| Ledger Facts | `financial_events`, `journal_entries`, `journal_lines` | الحقيقة المحاسبية القابلة للمراجعة |
| Derived Read Model | `getDashboardSummary` وقراءات الحسابات والحيازات | حسابات مشتقة للعرض والتحليل |
| External Market Data | `price_quotes`, `fx_rates`, `valuation_provenance`, `valuation_snapshots` | أسعار وتحويلات مؤرخة مع مصدر وحالة |
| Official Report Snapshot | `official_valuation_snapshots` | نسخة تقريرية ثابتة لصافي الثروة ومكوناته في وقت الالتقاط |

## حالة اللقطة

- `official`: توجد بيانات مقومة، وجودتها `current` أو `manual`.
- `review_required`: توجد بيانات مقومة، لكن يوجد مصدر `delayed` أو `stale` ويجب مراجعتها قبل اعتماد التقرير.
- `unavailable`: لا توجد بيانات كافية أو يوجد مصدر غير متاح يمنع تقريرًا صالحًا.

`last_known` لا يُعامل كبيانات حالية؛ يُصنف متقادمًا. والطابع المستقبلي غير صالح للتقرير.

## مكونات اللقطة

تحفظ اللقطة عملة الأساس، وقت التقييم، وقت الالتقاط، صافي الثروة، السيولة، قيمة الاستثمارات، الالتزامات، الربح غير المحقق، ومعرفات لقطات المكونات وموجز المصادر والتحذيرات. لا تحفظ كلمات مرور أو أسرارًا أو محتوى بريد.

## التشغيل

يستطيع المالك أو المستشار التقاط لقطة من صفحة التقييم. القراءة الأخيرة وسجل اللقطات محميان بنطاق مساحة FAMILY. كل التقاط يُسجل في `audit_events`. العملية Append-only ولا تحذف أو تعدل لقطة سابقة.

## سياسة التقادم

تستخدم الخدمة حد التقادم الموجود في Phase 3، وهو 48 ساعة. لا يوقف ذلك القراءة التشغيلية، لكنه يمنع إعلان اللقطة `official` إذا كانت الجودة متأخرة أو متقادمة. يجب على التقارير الرسمية عرض الحالة والتحذير بدل إخفاء المشكلة.

## حدود المرحلة

لا تشمل هذه المرحلة Lots، Health Score، FI، AI Advisor، Queue/Workers، أو إعادة تصميم Command Center. هذه تبقى ضمن مراحل لاحقة في خارطة الطريق المعتمدة.
